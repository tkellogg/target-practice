# Resume Export Plan

This document describes how the targeted resume is previewed and then exported (as a PDF). We aim for minimal differences between the Preview view and the final exported PDF.

---

## 1. Content
1. **Source**
   - Copy all sections from the master resume: All experience items, all projects, all education, all patents 
      - DO NOT alter the wording of anything
      - DO NOT use an LLM to format any of these
   - Generate Overview & Closing sections specific to this job, highlighting aspects that target this job posting

1. **Filtering**
   - Use an LLM to remove accomplishments & skills for each experience item & project that aren't relevant to this job posting
      - *Details*: When interacting with the LLM, use a random ID to select items (DO NOT allow the LLM to rephrase)
   - Perform filtering for experience & projects for each experience item & project
   - Filtering **ONLY** applies to accomplishments and skills

---

## 2. Preview vs. Export
1. **Identical Content**  
   - The preview and exported PDF show exactly the same information.  
   - The preview has special UI elements (e.g., badges or editing handles) that the PDF omits.

2. **Same Layout & Template**  
   - The overall template is consistent. The only difference is that the preview can include editing hooks or badges for LLM suggestions.

---

## 3. Flow & Interaction
1. **Preview Flow**  
   - The user lands on the preview screen, which displays the targeted resume.  
   - Data model has separate items for job title, company, dates, job desc,
   accomplishments, etc.
   - Each section (e.g., summary, job experience item, open-source project) may have a badge that shows the number of LLM-flagged issues.

2. **Generate Flow**
   - The user clicks "Generate" or "Regenerate"
   - The LLM generates opening & closing paragraphs.
   - In a different LLM call, for every job in the experience section, it 
   *selects* which bullet points to include. The LLM only emits temporary IDs,
   and the bullets are selected in code.

3. **Export Flow**  
   - The user clicks an “Export” button from the preview screen to generate a PDF.  
   - After the PDF is genrated, a "View PDF" button appears to the right of it.
   This View PDF button is always present if the PDF is available.
   - The system uses the same content that appears in the preview.  
   - There is a standard template for PDF export.
   - The PDF is saved according to the naming conventions detailed in [job-post-editor-plan.md](./job-post-editor-plan.md).

---

## 4. LLM Flagged Issues
1. **Badges or Indicators**  
   - Each content block (summary, experience item, etc.) can have a small indicator showing how many flagged issues exist.  
   - When clicked, a side-by-side view appears on the right to show the user the flagged issues.

2. **Types of Issues**  
   - **Missing Info**: Additional information could strengthen the content for the job.  
   - **Excess Info**: Contains details likely irrelevant or detrimental to the job.  
   - **Incorrect Info**: The cited information doesn't match the master resume.
   - Each of these issues is generated by a separate LLM call focusing explicitly
   on that issue and nothing else. They look across the resume, job description,
   and agreed upon goals.
   - The user can dismiss flags or open a text box to provide feedback for a “regeneration” of that section.

---

## 5. Regenerating Sections
1. **Item-Level Regeneration**  
   - Each flagged item can be revised by itself. Clicking “Regenerate” opens a prompt where the user can supply context or instructions. By "item", we're
   referring to top-level items, like a job in the experience section, or a 
   project.
   - The LLM then returns a fresh version of that specific section.

2. **Manual vs. Regenerated Updates**  
   - Users can edit the text manually in the preview via EditableText component.  
   - If they then choose to regenerate, the new LLM-generated content overwrites manual edits (the system does not merge them).

3. **No Version Storage**  
   - Regeneration does not store historical versions. Only the final version remains in the preview and subsequent export.

---

## 6. Final Export
1. **Push to PDF**  
   - Once the user is satisfied with the entire preview, they export to PDF.  
   - The exported PDF must precisely mirror the preview’s text and structure.
   - Use a well-defined template with holes for specific data items

2. **File Handling**  
   - The PDF follows the file naming system already outlined in [job-post-editor-plan.md](./job-post-editor-plan.md).  
   - No brand or watermark is applied.

---

## 7. Future Enhancements (Optional)
1. **Side-by-Side Comparison**  
   - In future updates, we may offer a way to view the original master resume text beside the newly targeted version.  
2. **Better Real-Time Updates**  
   - Potentially show the LLM’s suggestions immediately as the user types, although that’s not currently in scope.

---

## Summary
The plan emphasizes a two-step preview-and-export workflow with no differences in content. Users see LLM feedback through badges, can regenerate sections, and finalize a PDF that matches the preview. This approach simplifies targeted resumes for a specific role, trimming down the master resume without losing essential information.
